## status code

- 0: 识别到角色
- 1: 成功完成一次航海
- -1: 加载动画中，角色丢失
- -2: 航海失败
- -3: 同一 level 内累计战斗时间耗尽，归因于智能体
- -4: 加载或自动过关超时，属于引擎问题，不惩罚智能体

## 超时计时

| 超时 | 默认阈值 | 状态码 | 奖励处理 |
| --- | ---: | ---: | --- |
| 持续加载/角色丢失 | 5 秒，`timeout` | `-4` | 整步奖励为 0，无效训练样本 |
| 自动拾取、寻找出口 | 30 秒，`stay_timeout` | `-4` | 整步奖励为 0，无效训练样本 |
| 同一关战斗 | 60 秒，`combat_timeout` | `-3` | 超时分项 -10，仍保留本步其他正常奖励 |

直接创建 `Env()` 时战斗时限默认 60 秒；PPO 训练、续训及策略推理入口默认传入 30 秒。

战斗计时使用单调时钟，从第 1–4 关中首次发现敌人或危险弹幕开始。
同关期间累计，切换 level 或 `reset()` 后清零；起始区域不计时。
加载、无敌人且无危险弹幕的自动导航期间暂停，同关敌人重新出现后继续累计，
不会因为短暂丢失敌人就重置整个预算。成功、死亡或截断后停止计时。
在观测更新时检查预算，阻塞中的单次调用不会被硬中断。

```python
env = Env(timeout=5, stay_timeout=30, combat_timeout=60)
```

推理入口另有整局 `--max-episode-seconds` 默认 300 秒的外部运行预算，
耗尽时也作为 `-4` 执行截断处理，不冒充单关战斗超时。

## 智能体奖励

当前状态为 [v4 的 96 维编码](state-encoding.md)：敌人与子弹使用相对玩家坐标，
包含敌人实际碰撞框、3 个弹幕槽位和 8 个方向的静态碰撞标志。

`Env.step(action)` 继续返回状态码，并把本次奖励写入 `env.last_reward`，
各分项写入 `env.reward_terms`。每一步重新计算，不累计上一步的奖励。
`auto_step()` 是规则专家入口，不生成这套智能体奖励。

以公共控制器成功执行一次开火的 `+1` 为基准，默认奖励如下：

| 分项 | 数值 | 触发条件 |
| --- | ---: | --- |
| `fire` | `+1` | 冷却结束且存在射击方向，执行开火；不代表确认命中 |
| `fire` | `0` | 冷却中，或没有射击方向；撤离射击线不扣分 |
| `single_target_fire` | `+0.2` | 实际开火，且开火前恰好只有一个敌人 `can_hit=True` |
| `enemy_proximity` | 每个敌人最多 `-1/秒` | 距离敌人碰撞框不足 24 个逻辑像素，按平方权重叠加，见下文 |
| `step` | `0` | 默认不按决策次数收费 |
| `combat_time` | 每关累计 `-10` | 按消耗战斗预算的比例分摊 |
| `stationary` | `0` | 默认不因静止扣分 |
| `wall_collision` | `-0.1` | 预计下一小步路径撞到障碍、边界或战斗禁区 |
| `damage` | 每失去 1 HP `-10` | 有效观测中的血量下降；回血不给正奖励 |
| `next_level` | `+20` | 从第 1–3 关进入下一关，首次进入第 1 关不计 |
| `level_speed` | `0～+10` | 完成关卡时，按剩余战斗预算比例奖励 |
| `success` | `+50` | 整次航海成功，状态码 `1` |
| `death` | `-40` | 航海失败，状态码 `-2` |
| `timeout` | `-30` | 单关战斗超时，状态码 `-3` |

`can_hit` 复用 `Map.enemy_fire_flags()`，要求对齐、在射程内且无遮挡，不依赖敌人冷却。
两个及以上目标开火仍只有基础 `+1`，不加单目标奖励；不因保持或离开对齐状态单独奖惩。

近距离项为 `enemy_proximity_per_second × agent_combat_seconds × Σ max(0, 1 - d / D)²`，
默认每个敌人系数 `-1/秒`，`D=24`，`d` 为动作前玩家位置到敌人碰撞框的最短欧氏距离。
不要求敌人可射击或冷却结束；最短连线在静态膨胀地图上被墙阻隔时不计。
例如距一个敌人 12 像素，持续战斗 1 秒扣 `0.25`；两个这样的敌人扣 `0.5`。
计时复用本步主动控制阶段消耗的战斗预算，排除加载、自动拾取/过关耗时；
`update()` 已发生切关时不将新关时间归因给旧场景。距离是动作前采样的近似值。

正常步骤总奖励是分项之和；引擎问题 `-4` 的所有分项和总奖励均置 0。
例如：单目标实际开火的开火两项合计 `1.2`，再叠加本步时间、距离、碰撞等分项。
静止与撞墙不重复扣分。静止根据检测位置计算，避免地图可通行点修正掩盖静止，
但仍受目标检测抖动影响；`stationary_threshold` 可以调整容差。

撞墙是地图几何预判，不是游戏引擎提供的碰撞事件。左右、上下均检查 3 个逻辑像素，
斜向叠加为横向 3、纵向 3，逐格检查路径，不额外检查两侧格子；角色碰撞范围由扩张后的地图表示。
同时检查地图越界与战斗禁区；不会阻止动作执行，也不会计算战斗危险图。
敌人暂时消失可能来自遮挡和追踪波动，因此不把敌人数下降直接作为击杀奖励。

开火奖励在自动拾取/过关接管前保存，静止也在接管前判定，
不会将自动导航的开火和移动作为智能体自己的动作奖励。
自动接管后的有效血量变化和过关/终局仍计入当前步。
终局画面不提供可信血量，不因结算画面显示空白而额外扣除剩余 HP；
失败由死亡分项惩罚。终局/截断后必须 `reset()`，防止重复领取终局奖励。

训练时可使用五元组接口：

```python
state, status = env.reset()
if status == 0:
    next_state, reward, terminated, truncated, info = env.step_with_reward(action)
    print(reward, info["reward_terms"])
```

`terminated` 表示成功或死亡，`truncated` 表示战斗超时或引擎截断；
`info` 包含 `status_code`、`reward_terms`、`elapsed_seconds`、
`combat_elapsed_seconds`、`transition_valid`，以及开火前目标数 `fire_target_count`、
近距离权重 `enemy_proximity_weight`、主动控制战斗秒数 `agent_combat_seconds`。
`-3` 是有效训练样本；`-4` 的 `transition_valid=false`，训练时应丢弃该步，
不能只把零奖励的故障转移当作正常经验。捕获到其他 `TimeoutError` 时也映射为 `-4`，
并在 `info["error"]` 中记录异常信息。包含自动导航时，一步可能跨越多个画面，
`elapsed_seconds` 记录整步耗时；战斗时间成本按预算比例、近距离成本按主动控制的战斗秒数计算。
`step_with_reward()` 会执行一次 `step()`，不要对同一个动作再调用一次 `step()`。
推理入口在外部实施的整局时间预算不经过环境奖励函数。
在线训练通过 `train.train_ppo` 使用上述接口，故障步骤的丢弃、GAE 边界和续训说明见
[PPO 训练文档](ppo-training.md)。

调整奖励系数：

```python
from zaomeng_hanghai.env import Env
from zaomeng_hanghai.core.rewards import RewardConfig

env = Env(reward_config=RewardConfig(stationary=-0.005, wall_collision=-0.2))
```

这些系数是初始设计，尚未经过 PPO 实战调参。现有专家数据的 BC 训练仍只使用
观测和动作标签，不依赖奖励，也不会给已有专家记录补造奖励。

## 专家数据

专家战斗寻路的视野与射程分开计算：普通敌人非冷却时，以其位置为中心向四周
各延伸 `VISION` 个逻辑像素（含边界），构成穿墙正方形；第 4 关 Boss 非冷却时
视野覆盖全图。普通敌人和 Boss 开火冷却期间视野均清空，未知冷却按可开火处理。
`peek_region_enemy` 累计有效视野数，`peek_cross_enemy` 累计各敌人自身视野内的
碰撞框对齐区域数。`end_peek_region` 只保留能命中对应非冷却敌人的视野内安全终点，
`end_region` 排除所有有效视野覆盖的区域；实际射击仍受墙体、射程与对齐限制。

优先避让在途子弹和贴近敌人的危险，然后根据玩家位置选择终点：视野内只搜索
局部 `end_peek_region`，路径可在整张 `moveable_maze` 上绕行，不受视野边界限制；
局部终点无路时原地等待，不回退全局终点；视野外搜索 `end_region`。
搜索 `end_region` 时，通过可选 `cost_map` 对每个经过的格子额外收取
`2.0 × peek_region_enemy` 的成本，即按有效视野重叠敌人数叠加，粗搜索的中间格也计费。
该成本只影响路径选择，不启用脱险逻辑；局部终点搜索和避险搜索不传此额外成本。
该规则同样用于 Boss 战，敌人冷却不会清除在途子弹危险。

采集数据默认保存到项目根目录的 `data/expert/<运行目录>/`。
目录结构、过滤规则、NPZ 字段、状态编码和读取示例见 [专家数据格式](expert-data.md)。

## 图片手动检查碰撞与地图

所有归一化坐标转整数像素/网格的转换统一采用 `int(round(value))`，
包括实体、地图边界、障碍膨胀、图像裁剪和窗口操作坐标。
使用 Python `round` 的最近整数规则（恰好 `.5` 时取偶数）。点索引限制在有效网格内，
碰撞框用于数组切片的右/下边界允许等于宽/高；归一化浮点状态本身不取整。

```powershell
.\.venv\Scripts\python.exe -X utf8 tests/collision_test.py images/boss.png --map-index 0 --level 4
```

左图标记全部 YOLO 检测框（黄色虚线）、敌人控制器碰撞箱（绿色）、
玩家位置和 HIT 避弹范围（蓝色）、弹幕头部/方向及避让框（红色，已飞过玩家的为灰色）、
有效掉落物位置（粉色），以及当前与敌人对齐且无墙遮挡的射击连线。
白色 `x` 是修正前的浮点位置，彩色 `+` 是四舍五入/地图修正后的位置，两者用白线连接。
玩家 HIT 框来自避弹常量，不是游戏引擎直接提供的真实碰撞框。

右图叠加原始地图障碍框 `O`（橙色）、碰撞膨胀后的寻路障碍及边界（紫色）、
额外战斗禁区（红色）、地图内部边界（白色虚线）、出口与终点（当前目标黄色）和弹幕危险带。
障碍物取自 `Map` 的静态布局，不是从图片实时识别；原始障碍框的矩形集合精确覆盖障碍区域，
不会把凹形障碍之间的空地一起框进去。碰撞几何读取 `320×200` 坐标后映射回图片。
使用 `GameWindow` 正式感知流程的离线图片入口，不创建屏幕采集器或发送按键。
默认输入已裁剪好的游戏窗口截图；完整桌面截图可加 `--auto-crop`。
`--map-index` 和 `--level` 应匹配截图，以确保地图障碍与截图对齐、寻路点修正正确。
单张截图无法恢复敌人开火历史或冷却，图中不伪造冷却状态。

`--force-detect` 可在局部截图缺失血条/小地图时跳过加载/结算判断；仍保留界面遮罩处理。
`--save runs/manual/collision.png --no-show` 可只保存结果，
`--model`、`--conf` 可指定权重和置信度。
