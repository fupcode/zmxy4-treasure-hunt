# 航海寻宝环境

在项目根目录运行主程序，交互选择航海后输入需要胜利的次数（默认 3）：

```powershell
.\.venv\Scripts\python.exe main.py
```

也可以直接指定次数启动航海，默认不显示监控窗口，其余参数由航海子命令解析：

```powershell
.\.venv\Scripts\python.exe main.py voyage 3
```

`--debug` 仅显示监控窗口，仍会自动航海。`--read-only` 独立控制只读模式，不发送鼠标或键盘指令。
只读模式下可搭配 `--debug` 显示感知和建议路径，手动操作游戏，Ctrl+C 退出：

```powershell
.\.venv\Scripts\python.exe main.py voyage --read-only --debug --map-index 0 --level 1
```

`python main.py voyage --help` 查看航海参数。也可以通过
`python -m zmxy4_treasure_hunt.voyage.cli` 启动，参数相同。
`voyage/cli.py` 负责参数解析与启动，`voyage/env.py` 仅提供游戏环境和自动航海流程。

未开启监控窗口时，每连续战斗 10 秒输出一次 `[战斗 FPS]`。仅统计第 1–4 关完成入场后、有敌人或弹幕时的更新频率；过关导航、空场等待、加载和结算会重置统计，不混入战斗报告。

## 状态码

- `0`：识别到角色，继续运行。
- `1`：成功完成一次航海。
- `-1`：加载动画中或角色丢失，由 `update()` 等待恢复。
- `-2`：航海失败。
- `-3`：同一关内累计战斗时间耗尽。
- `-4`：加载或自动过关超时。

`reset()`、`auto_step()` 和 `auto_run()` 返回状态码。`auto_run()` 从重置开始运行一局；
`auto_loop(voyager, target=3)` 重复运行、根据状态码恢复游戏，直到达到目标胜利次数。

## 超时计时

| 超时 | 默认阈值 | 状态码 |
| --- | --- | --- |
| 持续加载/角色丢失 | 5 秒，`timeout` | `-4` |
| 自动拾取、寻找出口 | 60 秒，`stay_timeout` | `-4` |
| 同一关战斗 | 60 秒，`combat_timeout` | `-3` |

```python
from zmxy4_treasure_hunt.voyage.env import Voyager

voyager = Voyager(timeout=5, stay_timeout=60, combat_timeout=60)
```

战斗计时使用单调时钟，从第 1–4 关中首次发现敌人或危险弹幕开始。
同关期间累计，切关或 `reset()` 后清零；起始区域不计时。
加载、无敌人且无危险弹幕的自动导航期间暂停，同关敌人重新出现后继续累计。
成功、失败或超时后停止计时。在感知更新时检查预算，阻塞中的单次调用不会被硬中断。

## 开火反馈

保留 `ActionManager.fire_reward`：冷却结束且存在射击方向、执行开火时为 `1`，
冷却中或没有射击方向时为 `0`。它表示本次是否执行开火，不代表确认命中。
`fire()` 同时返回相同数值。

## 自动战斗与寻路

自动战斗寻路的视野与射程分开计算：普通敌人非冷却时，以其位置为中心向四周
各延伸 `VISION` 个逻辑像素（含边界），构成穿墙正方形；第 4 关 Boss 非冷却时
视野覆盖全图。普通敌人和 Boss 开火冷却期间视野均清空，未知冷却按可开火处理。
`peek_region_enemy` 累计有效视野数，`peek_cross_enemy` 累计各敌人自身视野内的
碰撞框对齐区域数。`end_peek_region` 只保留能命中对应非冷却敌人的视野内安全终点，
`end_region` 排除所有有效视野覆盖的区域；实际射击仍受墙体、射程与对齐限制。

优先避让在途子弹和贴近敌人的危险，然后根据玩家位置选择终点：视野内只搜索
局部 `end_peek_region`，路径可在整张 `moveable_maze` 上绕行，不受视野边界限制；
局部终点无路时原地等待，不回退全局终点；视野外搜索 `end_region`。
搜索 `end_region` 时，通过可选 `cost_map` 对每个经过的格子额外收取
`2.0 × peek_region_enemy` 的成本，即按有效视野重叠敌人数叠加，粗搜索的中间格也计费。
该成本只影响路径选择，不启用脱险逻辑；局部终点搜索和避险搜索不传此额外成本。
该规则同样用于 Boss 战，敌人冷却不会清除在途子弹危险。

子弹避让使用独立安全余量 `BULLET_MARGIN=3`：横向半宽为
`HIT_WIDTH + BULLET_MARGIN`，纵向半高为 `HIT_HEIGHT + BULLET_MARGIN`。
四向危险带仅增加侧向余量，从子弹中心沿前进方向延伸至 `FIRE_X_RANGE` /
`FIRE_Y_RANGE`（96 / 100 像素），不增加前端长度；后方延伸原始碰撞半径
`HIT_WIDTH`（水平移动）或 `HIT_HEIGHT`（垂直移动），不叠加安全余量；危险值仍逐弹累加。
危险带、弹体障碍和距离成本图的所有切片均裁剪到地图边界，右/下边界包含安全半径端点。
子弹中心沿运动方向超过玩家横向 `HIT_WIDTH` / 纵向 `HIT_HEIGHT` 后，才可归为已通过的安全子弹，
恰好位于边界时仍归为危险。手动碰撞可视化同步显示含余量的范围。

构建寻路地图时，若玩家已在某颗子弹含余量的障碍矩形内，则不写入该颗子弹的硬障碍，
但照常累加危险值、保留距离成本与安全终点筛选；多颗覆盖玩家的子弹分别处理。
静态墙和其他子弹的障碍不清除。下一次地图更新时玩家若已撤出，该子弹恢复为硬障碍。

子弹感知仅在 YOLO 子弹框内提取弹头颜色，选择最大有效弹头轮廓定位；
以弹头相对子弹检测框中心的偏移判断四向运动，不再依赖火焰颜色、火焰面积或包含关系。
没有有效弹头或弹头恰好位于框中心时跳过该框；方向精度仍依赖 YOLO 框与弹头定位。

## 图片手动检查碰撞与地图

所有归一化坐标转整数像素/网格的转换统一采用 `int(round(value))`，
包括实体、地图边界、障碍膨胀、图像裁剪和窗口操作坐标。
使用 Python `round` 的最近整数规则（恰好 `.5` 时取偶数）。点索引限制在有效网格内，
碰撞框用于数组切片的右/下边界允许等于宽/高；归一化浮点坐标本身不取整。

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/voyage_collision_test.py images/boss.png --map-index 0 --level 4
```

左图标记全部 YOLO 检测框（黄色虚线）、敌人控制器碰撞箱（绿色）、
玩家位置和 HIT 避弹范围（蓝色）、弹幕头部/方向及避让框（红色，已飞过玩家的为灰色）、
有效掉落物位置（粉色），以及当前与敌人对齐且无墙遮挡的射击连线。
白色 `x` 是修正前的浮点位置，彩色 `+` 是四舍五入/地图修正后的位置，两者用白线连接。
玩家 HIT 框来自避弹常量，不是游戏引擎直接提供的真实碰撞框。

右图叠加原始地图障碍框 `O`（橙色）、碰撞膨胀后的寻路障碍及边界（紫色）、
额外战斗禁区（红色）、地图内部边界（白色虚线）、出口与终点（当前目标黄色）和弹幕危险带。
障碍物取自 `Map` 的静态布局，不是从图片实时识别；原始障碍框的矩形集合精确覆盖障碍区域，
不会把凹形障碍之间的空地一起框进去。碰撞几何读取 `320×200` 坐标后映射回图片。
使用 `GameWindow` 正式感知流程的离线图片入口，不创建屏幕采集器或发送按键。
默认输入已裁剪好的游戏窗口截图；完整桌面截图可加 `--auto-crop`。
`--map-index` 和 `--level` 应匹配截图，以确保地图障碍与截图对齐、寻路点修正正确。
单张截图无法恢复敌人开火历史或冷却，图中不伪造冷却状态。

`--force-detect` 可在局部截图缺失血条/小地图时跳过加载/结算判断；仍保留界面遮罩处理。
`--save runs/manual/collision.png --no-show` 可只保存结果，
`--model`、`--conf` 可指定权重和置信度。
